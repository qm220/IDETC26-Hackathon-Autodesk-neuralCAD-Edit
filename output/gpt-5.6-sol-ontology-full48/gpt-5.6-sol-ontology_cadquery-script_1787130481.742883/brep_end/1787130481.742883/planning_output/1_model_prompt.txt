You are given:

1. Multi-view rendered images of a mechanical CAD model.
2. A CadQuery STEP/B-rep analysis report containing deterministic geometric
   information about the model, including solids, faces, surface types,
   dimensions, centroids, axes, bounding boxes, and other available topology.
3. The Hierarchical CAD Model Ontology, which defines the controlled
   vocabulary for sections, features, functions, physical behaviors,
   interfaces, relationships, B-rep faces, and semantic face roles.

Your task is to construct an ontology-grounded semantic representation of the
CAD model and connect the semantic interpretation to the exact B-rep FACE
entities reported by CadQuery.


IMPORTANT PRINCIPLES

A. GEOMETRIC TRUTH

The CadQuery STEP analysis is the authoritative source for:
- solid IDs
- face IDs
- surface types
- dimensions
- centroids
- axes/directions
- bounding boxes
- adjacency/topology where available

Never invent a B-rep ID or deterministic geometric property.
Only use IDs appearing in the supplied CadQuery analysis.


B. SEMANTIC INFERENCE

The multi-view images and geometric information should be used together to
infer:
- sections
- engineering features
- functional intent
- physical behavior
- interface roles
- semantic relationships
- semantic roles of B-rep faces

These are interpretations and should be distinguished from deterministic
CadQuery observations.


C. ONTOLOGY GROUNDING

Use the supplied ontology as the controlled semantic vocabulary.

For every semantic entity, assign the most specific applicable ontology class.

Do not invent new ontology classes or relationship types.

If none of the supplied ontology classes adequately represents an entity:
- use the closest valid parent/general class;
- preserve the more specific interpretation in the human-readable "name" or
  "description";
- optionally record that ontology coverage is incomplete.


D. B-REP FACE GROUNDING

Whenever possible, connect semantic features to the exact FACE IDs that
physically realize them.

A semantic feature may contain:
- one B-rep face;
- multiple B-rep faces;
- repeated face instances;
- representative faces from a repeated pattern.

Do not assume that one feature corresponds to one face.

Only FACE-level B-rep entities are represented in the semantic model.

Boundary geometry required during later CAD operations should be derived
programmatically from the grounded faces during CAD execution rather than
represented as separate semantic entities.


E. VIEW ORIENTATION

Labels such as "+X", "-X", "+Y", "-Y", "+Z", and "-Z" on the
rendered images describe CAMERA / CAD VIEW DIRECTIONS ONLY.

They MUST NOT automatically be interpreted as the human-semantic front,
back, top, bottom, left, or right of the object.

Identify the object and determine the most likely human-semantic orientation
independently from the CAD camera directions.

When describing location:

1. Prefer relationships to other sections/features and exact geometric references.
2. Use human-semantic directions when they can be inferred with reasonable confidence.
3. Use CAD-coordinate/view information as auxiliary geometric information when useful.

For example, prefer:

"between the two clevis ears"
"surrounding the central bore"
"radially outside the hub"
"attached to the mounting flange"

over:

"front-left part of the object".


==================================================
STEP 1 — PART AND SOLID INTERPRETATION
==================================================

Determine:
- part/model name if identifiable;
- overall mechanical description;
- number of solids/components from CadQuery;
- whether the solids appear to represent separate functional components or
  disconnected geometry;
- major symmetry, periodicity, or repeated structures;
- likely semantic orientation of the object;
- use the coordinate system in the pictures as auxiliary information.

Preserve the exact CadQuery solid IDs.

Do not infer that CAD Solid 0 is necessarily the "main" component simply from
its index.


==================================================
STEP 2 — SECTION DECOMPOSITION
==================================================

Divide the model into meaningful Sections.

A Section is a relatively large functional/structural portion of the model,
such as:
- mounting region;
- central body;
- hub region;
- spoke/web region;
- outer rim;
- housing;
- cradle;
- roller assembly.

Sections are NOT individual fillets, holes, ribs, bosses, or faces.

For each section determine:
- unique ID: R01, R02, ...
- name;
- ontology class;
- description;
- relative location;
- associated CAD solids;
- RGB display colour;
- engineering functions;
- physical behaviors.

Sections should collectively cover the meaningful structure of the model.


==================================================
STEP 3 — STRUCTURAL FEATURE IDENTIFICATION
==================================================

Within each Section, identify distinct Features.

Examples include:
- holes;
- slots;
- grooves;
- cavities;
- pockets;
- bosses;
- ribs;
- webs;
- spokes;
- shells/walls;
- flanges;
- lugs;
- forks;
- teeth;
- hubs;
- fillets;
- chamfers;
- mounting interfaces;
- pin interfaces;
- spline interfaces.

For every feature provide:
- unique ID: F001, F002, ...
- name;
- ontology class;
- parent section;
- optional parent/compound feature;
- description;
- engineering function;
- physical behavior;
- interface role where applicable.

Do NOT classify an entire section as a single feature merely because the section
has one dominant function.

A section may contain many features.


==================================================
STEP 4 — REPEATED FEATURES AND PATTERNS
==================================================

Detect repeated geometrically/semantically equivalent features.

Examples:
- four mounting holes;
- repeated sprocket teeth;
- repeated spline teeth;
- repeated spokes;
- repeated ventilation slots.

Represent these using a FeatureGroup / RepeatedFeatureGroup where appropriate.

Record:
- group ID;
- member feature IDs where practical;
- ontology feature class;
- pattern type;
- approximate or exact member count if supported;
- representative feature(s);
- symmetry/periodicity information.

Do not unnecessarily enumerate hundreds of nearly identical features if a
pattern representation is more informative.


==================================================
STEP 5 — FUNCTION AND PHYSICAL BEHAVIOR
==================================================

For every important section and feature distinguish:

FUNCTION:
What engineering purpose does it serve?

Examples:
- transfer load;
- transmit torque;
- mount;
- locate;
- support;
- guide;
- connect;
- engage;
- constrain motion;
- provide clearance;
- protect;
- contain.

PHYSICAL BEHAVIOR:
What physical/mechanical behavior allows it to perform that function?

Examples:
- carries tension/compression;
- carries shear;
- resists bending;
- resists torsion;
- reacts bearing load;
- distributes stress;
- provides contact;
- permits rotation;
- constrains translation.

Use ontology classes where available and retain a concise natural-language
explanation.

Do not confuse function with geometry.


==================================================
STEP 6 — RELATIONSHIP GRAPH
==================================================

Create explicit relationships between sections and between features.

Use ONLY relationship types defined in the supplied ontology.

Consider three categories:

STRUCTURAL / TOPOLOGICAL
Examples:
- partOf
- contains
- attachedTo
- adjacentTo
- blendsInto
- sharesBoundaryWith

GEOMETRIC / SPATIAL
Examples:
- coaxialWith
- concentricWith
- parallelTo
- perpendicularTo
- alignedWith
- offsetFrom
- inside
- surrounds
- between

FUNCTIONAL
Examples:
- transmitsLoadTo
- supports
- locates
- guides
- constrains
- providesClearanceFor
- engagesWith
- mountsTo

Represent each relationship explicitly as:

{
  "source": "",
  "relation": "",
  "target": "",
  "confidence": null
}

Do not combine multiple relationships into a semicolon-separated text string.


==================================================
STEP 7 — B-REP FACE GROUNDING
==================================================

Use the CadQuery STEP analysis to map semantic sections and features to exact
B-rep FACE IDs.

For important faces, record:
- B-rep ID exactly as reported by CadQuery;
- entity type;
- parent feature;
- semantic role;
- short name;
- description;
- salience;
- confidence;
- evidence used for the match.

Possible evidence includes:
- surface type;
- radius;
- dimensions;
- axis;
- centroid;
- bounding box;
- adjacency;
- visual correspondence;
- repeated-pattern correspondence.

Possible semantic face roles include:
- bore_wall;
- mounting_face;
- seating_face;
- interface_face;
- outer_wall;
- cavity_wall;
- tooth_flank;
- tooth_tip;
- root_blend;
- fillet_surface;
- chamfer_surface;
- support_face;
- transition_surface.

Use ontology-defined roles where available.

Do not invent FACE IDs.

A feature may be represented by multiple faces.

For features such as holes, fillets, chamfers, grooves, ribs, or interfaces,
identify the faces that most directly realize the semantic feature.


==================================================
STEP 8 — REMAINING B-REP FACE COVERAGE
==================================================

After identifying semantically important B-rep faces, account for all
remaining FACE IDs from the CadQuery analysis.

Assign each remaining face to the most likely:

1. Feature, if identifiable;
2. otherwise Section.

These faces do not need detailed semantic descriptions if they are small,
repeated, or low-salience.

Do NOT treat these faces as meaningless "minor faces".

Record them as secondary/unclassified B-rep faces so that every FACE ID
remains associated with the semantic model.

Compact inclusive ranges may be used for large consecutive repeated sets,
provided explicitly described important faces are excluded from those ranges.


==================================================
STEP 9 — VALIDATION
==================================================

Before producing the output verify:

1. Every referenced FACE ID exists in the supplied CadQuery report.
2. Every feature belongs to a valid section.
3. Every relationship references existing semantic IDs.
4. Every ontology class/property comes from the supplied ontology.
5. No deterministic geometric property contradicts CadQuery.
6. Repeated features are represented consistently.
7. Every CadQuery FACE is accounted for by a feature or section.
8. CAD camera labels have not been incorrectly treated as semantic orientation.
9. Uncertain semantic interpretations are marked with confidence rather than
   presented as geometric facts.
10. No boundary-level B-rep entities have been introduced into the semantic
    representation.


==================================================
OUTPUT
==================================================

Return ONLY valid JSON.
Do not use Markdown fences.

Ontology class, role, function, behavior, and relation values MUST use the
cad: prefix from the Hierarchical CAD Model Ontology (for example
cad:ThroughHoleFeature, cad:BoreWallRole, cad:MountFunction, cad:coaxialWith).
Colours must be visually distinct across sections.

In semantic_orientation, also fill view_sides so each CAD camera label maps to
the most likely human-semantic side of the object (or "unknown").
